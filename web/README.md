# Whistleblower · web demo

Browser-based demo of the Whistleblower pipeline. Compiles
[`web-demo/`](../web-demo/) (Rust → WASM via wasm-bindgen) and serves it from a
Next.js page where evaluators can try the upload → broadcast → anchor flow without
installing the Logos Basecamp.

## Local dev

```bash
# from repo root
cd web
npm install
npm run dev           # this also runs `wasm-pack build` on web-demo/
open http://localhost:3000
```

Prerequisites:
- Node 18+
- [`wasm-pack`](https://rustwasm.github.io/wasm-pack/installer/) — `cargo install wasm-pack`
- `rustup target add wasm32-unknown-unknown`

The `npm run wasm` script invokes `wasm-pack build --target web --out-dir ../web/lib/pkg`
which compiles the Rust `web-demo` crate to a browser-loadable ES module.

## Build for Vercel

```bash
npm run build         # runs wasm-pack + next build
```

The Vercel deployment config in [`vercel.json`](../vercel.json) at the repo root
runs the same `npm run build` after installing `wasm-pack` and the wasm32 target
in the build container.

## What's here

| Path | Purpose |
|---|---|
| `app/page.tsx` | The main demo UI — file picker + metadata form + live state visualization of Codex / Waku / LEZ layers + lookup + activity log |
| `app/layout.tsx` | Root layout, Tailwind imports |
| `app/globals.css` | Tailwind base + CSS custom properties for the dark theme |
| `lib/pkg/` | Generated WASM artifacts (gitignored, regenerated by `npm run wasm`) |
| `next.config.js` | Next.js config with `asyncWebAssembly: true` |
| `tailwind.config.js` | Tailwind setup |

## What's NOT here

The Rust source for the WASM lives in [`../web-demo/`](../web-demo/). The
production module (the one that ships as a Basecamp `.lgx`) lives in
[`../crates/doc-index-core/`](../crates/doc-index-core/). The demo and the
production module share wire types via
[`../crates/registry-core/`](../crates/registry-core/) so this UI matches what
the real Basecamp app will display once the Logos backends are wired in.
